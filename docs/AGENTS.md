# Docs del front: reglas y diseño

`architecture.md` conserva las reglas canónicas del front; `guides/premisas-de-desarrollo.md`, las premisas de todas las pantallas; `design/visual-baseline.md`, decisiones visuales aprobadas y procedencia; `mapa-de-instrucciones.md`, puntos de entrada por carpeta.

`guides/mensajes-y-estados.md` es el contrato transversal de mensajes; `plans/2026-09-30-unificacion-mensajes.md`
separa diseño, inventario y adopción pendiente. Los resúmenes enlazan el contrato, no duplican ni
redefinen duraciones o canales. Un plan propuesto no se presenta como código implementado.

## Al modificar

- Los planes históricos del backend no reemplazan las reglas vigentes de estructura ni el contrato visual.
- Una decisión visual se registra junto al cambio de tokens o UI y la biblioteca. Las propuestas sin elección no se convierten en reglas.
- Las guías por carpeta enlazan el detalle y se actualizan cuando cambia una responsabilidad; evitá duplicar todo el contrato visual.
- Las rutas de archivo dentro de la guía canónica se expresan desde la raíz del repo.
